知识树总览

昨天你看到了路径。今天我们把零散的知识挂到两棵树上。
AI 一棵。CS 一棵。

AI 知识树

AI 是怎样一层一层长出来的

不是把一堆概念塞给你。是从底往上——每一层解决一个问题，每一层是下一层的基础。

第一层
模型架构——让机器能"懂"
不是让机器变聪明，是让机器能处理语言。核心问题：怎么让机器在读了一个句子之后，知道每个词跟其他词之间是什么关系。
  • Pre-Transformer 时代：RNN、LSTM、GRU——从左到右一个一个词读，读到最后前面的忘了。效率低，训练慢。
  • Transformer (2017)："Attention Is All You Need"——不再一个词一个词读，所有词同时互相对视。每个词问所有其他词"你跟我什么关系"，然后按关系权重决定自己该吸收什么。这是整个现代 AI 的地基。没有它就没有后面的一切。
  • Scaling Law (2020)：不是改架构，是发现"你把同一个架构做大，能力会自己冒出来"。GPT-1 到 GPT-2 到 GPT-3——参数从 1 亿到 1750 亿，涌现了 nobody 专门训练过它的能力。这改变了行业——大家不再忙着设计新架构，开始拼命做大模型。
  • Mixture of Experts (MoE)：一个模型里有多个专家子网络，每个 token 激活不同子集。不是所有参数都在同时工作——所以可以在不增加推理成本的前提下把参数做大。GPT-4 和 Mixtral 用这个。
第二层
交互范式——让人知道怎么跟它说话
模型能处理语言了，但你跟它说话的方式会极大影响它说什么。核心问题：怎么把模糊的人类需求翻译成模型能精准回应的格式。
  • Prompt Engineering (2020-2023)：从"随便写一句"到"写系统提示词、给 few-shot 示例、设角色、限格式"。本质上是你发现——你跟它说的第一句话，就是它接下来全部行为的轨道。你说"你是一个严格的代码审查者"，它就会按那个角色往下走。
  • Chain-of-Thought (2022)：不是直接让它给答案，是让它先"一步一步想"。想完了再给答案——准确率大幅提升。不需要改模型，不需要重新训练，只是改了你说的话的结构。这是 prompt 的巅峰——用语言本身让模型执行了它没有专门训练过的推理流程。
第三层
知识接地——让模型能查东西
模型再强，它的知识截止于训练日期。你不知道的事它也不知道。核心问题：让模型在回答之前先看一眼外面的世界。
  • RAG (Retrieval-Augmented Generation, 2020-)：用户提问 → 系统先去外部知识库（文档、数据库、搜索引擎）检索相关内容 → 把检索结果和用户的问题一起塞进 prompt → 模型基于这些实时检索到的信息回答。不是"让模型记住更多"，是"让模型不需要记"。
  • Fine-tuning vs RAG：微调是把知识烧进模型参数里→贵、慢、知识过期了要重新烧。RAG 是把知识放在外面→便宜、快、更新文档就等于更新了知识。后来大家发现两者可以共存——模型的基础能力靠预训练+微调，具体的事实靠 RAG 检索。
第四层
行动能力——让模型能用工具和做决策
之前都是"它说一句话，你说一句话"。现在它开始自己动手了。核心问题：怎么让模型不只是说话，还能做事、调用工具、在多步骤任务里自己决定下一步。
  • Function Calling / Tool Use (2023-)：不只是让模型输出文字，让它输出"我要调用这个 API，参数是这些"。你给模型一堆工具的描述，它自己判断什么时候该用哪个、传什么参数。这是 agent 的起搏器——模型从"嘴"变成了"手"。
  • Agent 架构 (ReAct, 2022; MRKL, 2022)：不再是"我说一句你做一下"，而是"你有一个目标，你自己决定每一步做什么、观察结果、调整下一步"。思考→行动→观察→再思考，循环直到目标达成。
  • 自纠正 (Reflexion, 2023)：agent 执行失败 → 回头看刚才发生了什么 → 用自然语言给自己写一段反思 → 带着反思重新来。不是人类告诉它错在哪——是它自己诊断自己。
第五层
工程化——让 agent 从实验室到生产
agent 跑通了，但你不可能每次都从零搭。核心问题：怎么把 agent 变成可复用的、可评估的、可管理的工程体系。
  • Orchestration 框架 (LangChain, 2022; LlamaIndex, 2023; CrewAI, 2024; AutoGen, 2024)：把 agent 的组件——提示词模板、工具列表、记忆模块、反思循环——做成可组合的积木。你不需要每次自己写 ReAct 循环，框架替你搭好了。
  • Harness / Agent Management：不只是搭一个 agent，是管理一群 agent、监控它们的执行、在它们跑偏时拉回来。这层还在早期，但它是 agent 从"好玩"到"能用"的必经之路。
  • Evaluation：你怎么判断一个 agent 好不好？传统 benchmark 测不了 agent——因为 agent 是多步决策，不是单次回答。
第六层
认知架构——重新思考"智能"本身
前面五层都在把现有架构用到极致。这一层问的是：现在的架构本身是不是走偏了？
  • World Model (LeCun, 2022)：你现在用的 LLM 本质上是在做"预测下一个 token"——它没有真正的世界模型，没有物理常识，没有"如果我推这个杯子它会掉下去"的因果推理。LeCun 的 proposal 是给 AI 加一个内部的"世界模拟器"——它能自己想象"如果我做 X 会发生什么"，然后根据想象的后果做决策，而不是靠统计模式匹配。
  • System 1 vs System 2 (Kahneman 的概念被引入 AI)：当前 LLM 本质上是 System 1——快、直觉、统计模式匹配。真正的智能需要 System 2——慢、推理、多步规划。怎么在 transformer 基础上加一层 System 2 的推理，是 2024-2025 年的前沿。
CS 知识树

计算机是怎么一层一层搭起来的

从一堆硅和金属，到你今天对 AI 说一句话——中间隔了九层。每一层都有人替你做了。

第一层
物理地基——电怎么变成计算
这一层的核心问题是"一堆硅和金属，怎么能做加减乘除"。
  • 晶体管 → 逻辑门 → ALU：晶体管是电子开关，逻辑门（与、或、非）把开关组合成基本逻辑，ALU 把逻辑门组合成能算加减乘除的单元。这就是 CPU 的心脏。
  • 冯·诺依曼架构：CPU（计算）+ 内存（暂存）+ 输入/输出。这是 1945 年画的图，你现在的电脑还是它。程序和数据放在同一个内存里——这是它最大的革命：程序不再是硬件，是可以改的软件。
  • 内存层级：寄存器（CPU 内部，最快，最小）→ L1/L2/L3 缓存 → RAM → SSD/硬盘 → 网络存储。越近越快越贵越小。所有性能优化的本质都是"把数据往左移"。
  • 二进制与编码：为什么一切都用 0 和 1？因为晶体管只有开和关两个状态。ASCII 用 7 位二进制代表 128 个字符，Unicode 用更长的编码覆盖了所有人类文字。你敲的每一个字，底下全是 010101。
第二层
操作系统——让硬件能被程序用
一台裸机只能跑一个程序。操作系统解决的问题是"怎么让一百个程序同时跑，还互不踩踏"。
  • 进程与线程：进程是"一个正在运行的程序"，线程是"进程内部的一条执行路径"。一个进程可以开多个线程——浏览器一个标签页一个线程，一个崩了不影响别的。
  • 内存管理：每个进程以为自己在用全部内存（虚拟内存），实际上 OS 在背后把一个进程的大片虚拟地址映射到物理内存的不同碎片上。你在 CS50 里碰到的指针，指的就是内存地址。
  • 文件系统：硬盘上不是"一个文件一个坑"。一个文件被切成无数小块散落在硬盘各处，OS 维护一张表——"文件 A 的第一块在哪个扇区、下一块在哪"。你删一个文件只是删了这张表的入口，数据还在，直到被覆盖。这就是数据恢复的原理。
  • 驱动与设备管理：打印机、键盘、鼠标、显卡——OS 给每个设备一个抽象接口。程序说"打印"，不需要知道打印机是什么型号。
第三层
数据与存储——信息怎么活下来
内存一断电就没了。这一层解决的是"怎么让数据有记忆"。
  • 数据结构：数组（连续存放，随机访问快）、链表（一个一个串起来，插入删除快）、栈（后进先出，函数调用就靠它）、队列（先进先出）、哈希表（给数据算一个编号，直接找到坑，O(1) 查找）、树（分层组织，数据库索引靠 B-Tree）。你的"看见→记住→出去"里，数据存哪、用什么结构找——全在这。
  • 数据库：文件存数据太慢，数据库把"存"和"查"都做了极致优化。关系型数据库（SQL）—用表格组织，用 SQL 问"去年消费超过 1000 的客户有哪些"。非关系型（NoSQL）—用文档或键值对存，更灵活但不保证一致性。
  • 事务与一致性：银行转账，钱从 A 扣了但还没加到 B——如果中间断电了怎么办？事务保证要么全做完，要么全回滚。ACID 原则：原子性、一致性、隔离性、持久性。
第四层
编程语言与编译器——人话怎么变成机器话
机器只认识二进制指令。这一层的问题是"人写的 if 语句，怎么变成几十条机器指令"。
  • 机器码 → 汇编 → 高级语言：机器码是 0101 直接喂 CPU。汇编是给每条机器指令起了个人能读的名字（MOV、ADD、JMP）。C 是一句顶几十条汇编。Python 是一句顶几十句 C。这就是为什么 Python 慢——它在 C 的毯子下面偷偷帮你干活。
  • 编译 vs 解释：C 是编译型——写完代码，编译器一次性翻译成机器码，跑得快。Python 是解释型——一行一行翻译，边跑边翻，慢但改完立刻能跑。Java 在中间——先编译成中间码，再在 JVM 上跑。
  • 类型系统：静态类型（C、Java，编译时就知道类型）vs 动态类型（Python、JS，运行时才知道）。强类型（不允许"数字"+字符串）vs 弱类型（JS 自动帮你转，出问题不告诉你）。这就是为什么学 C 再学 Python 更容易——C 让你知道"类型"到底是什么意思。
第五层
算法与复杂度——怎么做得快
数据量涨到一亿条，直觉做法就行不通了。这一层问"哪种做法不会让我等到天荒地老"。
  • 时间复杂度：不是算具体秒数，是算"数据量翻倍后，时间怎么变"。O(1) 不管多少数据都一瞬间。O(log n) 每次排除一半（二分查找）。O(n) 数据翻倍时间翻倍。O(n²) 数据翻倍时间翻四倍——你大学处理数据时卡死的那些脚本，大概率是 O(n²) 当 n 很大时爆炸了。
  • 排序算法：冒泡排序 O(n²) 没人用。快速排序 O(n log n) 是默认方案。但为什么有时候用插入排序？因为当数据量很小时，O(n²) 的常数项比 O(n log n) 小——算法不是越高级越好，是在当前数据量下谁更快。
  • 搜索与图：Dijkstra 找最短路径（导航靠它），A* 是 Dijkstra 加了一个方向感（往目标方向猜着走）。二分查找的前提是数据排好序——为什么数据库要建索引？就是把无序数据变成有序，让查找从 O(n) 变成 O(log n)。
  • 递归与动态规划：把大问题拆成小问题，小问题拆到最简。递归是自己调用自己——斐波那契数列、文件夹遍历。动态规划是把已经算过的答案存起来不重复算。
第六层
软件架构——大系统怎么不塌
一个文件几千行代码就开始乱了。这一层问"当代码多到一个人看不过来，怎么组织"。
  • 模块化与抽象：把代码拆成"这个函数只管一件事"。输入什么，输出什么，中间的细节外面看不见。这就是抽象——你不需要知道 sort() 怎么排的，你只需要知道"放进去一个列表，出来一个排好序的列表"。
  • 设计模式：前人踩了无数坑后总结出来的可复用模板。工厂模式（统一造对象的接口）、观察者模式（一旦有变化自动通知所有人）、单例模式（全局只有一个实例）。不是背下来——是在你碰到类似问题时，发现"哦这个有人已经想过了"。
  • 架构模式：MVC（模型-视图-控制器，前端框架的祖宗）、微服务（不是一个大程序，是一群小程序互相通信）、事件驱动（不是轮询等结果，是"这件事发生的时候叫醒我"）。
  • 技术债：今天赶工省了一个小时没写好文档、没做测试、偷懒用了一个临时的硬编码值。以后每次改这个系统，那个小时都会变成利息跟着你。Martin Fowler 说技术债——和钱一样，欠债可以，但要知道利息是多少、什么时候还。
第七层
网络与互联网——机器怎么跟机器说话
你的电脑是一台孤岛。这一层问"我在北京敲一个回车，上海那台机器怎么知道的"。
  • TCP/IP 协议栈：应用层（HTTP，网页用的）→ 传输层（TCP，保证不丢包、按序到达）→ 网络层（IP，找到目标机器的地址）→ 链路层（把数据变成电信号或光信号发出去）。你发的每一条微信都穿了这四层衣服。
  • DNS：你打"google.com"，DNS 把它翻译成 142.250.80.46。没有 DNS，你得记住所有网站的 IP 地址。DNS 是互联网的电话簿——而且是层层缓存的：本机、路由器、运营商、根域名服务器。
  • HTTP / HTTPS：浏览器和服务器之间的对话规则。GET 是"给我这个页面的内容"，POST 是"我提交了一组数据给你处理"。HTTPS 加了一个锁——所有内容加密传输，中间人看不到你在跟服务器说什么。
  • 负载均衡与 CDN：你一个人访问，一台服务器够。一百万人同时访问，一台服务器炸了。负载均衡把请求分给多台服务器——每台处理一部分。CDN 把静态资源（图片、CSS、JS）存到离用户最近的节点——你在上海访问，北京的不给你发，上海的节点发。
第八层
工程化——从实验室到用户
代码在你自己电脑上跑通只是开头。这一层问"怎么确保今天改的代码不会让昨晚能用的功能死掉"。
  • 版本控制（Git）：不是"另存为最终版 3"。Git 跟踪每一次修改，能回到任何一个历史状态。分支（branch）让你在一个副本上做实验，做坏了不影响主线。合并（merge）把实验结果融回主线。团队协作的基础——没有 Git，两个人同时改一个文件就互相覆盖。
  • 测试：单元测试测单个函数，集成测试测多个模块在一起跑，端到端测试模拟用户操作。没有测试的系统是危房——你每次改东西都在赌不会塌。
  • CI/CD：持续集成（代码推到仓库 → 自动跑测试 → 测试不通过不许合入）、持续部署（测试通过 → 自动更新线上服务器）。不是"上线发邮件通知所有人"，是代码推上去就自己走完整个流水线。
  • 监控与日志：线上出问题了你怎么知道？日志记录每次请求的细节，监控盯着 CPU、内存、错误率。报警——错误率超过 1% 自动发短信。
第九层
元层——编程作为一种思维
这一层和具体的语言、工具、框架无关。它问的是"编程教给我的思维，在我离开电脑之后还能用在哪"。
  • 计算思维：分解（大问题拆成小问题）、模式识别（这个问题和以前哪个问题是同构的）、抽象（忽略细节看本质）、算法设计（一步一步怎么走）。你在做的"看见→记住→出去"不是教学技巧——是你用计算思维把自己泡出来的东西翻译成了课程。
  • 伪代码：不是你写给 AI 看的那段东西——是你在脑子里用最干净的逻辑描述一件事，然后才能决定谁来实现它（你自己、AI、团队）。CS50 说 pseudocode 是为了让别人理解你的决策——对，但更深的一层是：伪代码是你和自己的对话。你只有先跟自己说清楚"我要干嘛"，才能跟任何人或任何东西说清楚。
  • 计算机的局限性：计算机不是万能的——有些问题（停机问题）数学上已被证明不可能用算法解决；有些问题（NP 完全问题）理论上能解但宇宙毁灭都跑不完；有些问题不是算法问题——是定义不清、需求矛盾、人的因素。你教的不只是"怎么用 AI"，更是"遇到 AI 搞不定的事时怎么判断是'它不行'还是'我没说清楚'还是'这件事本身就没有干净解'"。
为什么不一样

九层和六层，不是数量问题

CS 九层，AI 六层。不是因为 CS 更大——是结晶度的问题。原因有三层。

第一层：时间
CS 的地基是 1945 年冯·诺依曼画的。到现在 81 年。AI 的地基——Transformer——是 2017 年发表的。到现在 9 年。81 年的东西和 9 年的东西，结晶度当然不同。
  • CS 这八十多年里，每一层都是无数人踩过坑、写过教材、推翻过旧范式、收敛出新共识之后留下的骨头。
  • AI 还在长肉——你读 LeCun 的 World Model 时那种"他在提出方向不是在总结结论"的感觉，就是肉还没变成骨头。
第二层：因果关系方向相反
CS 是从底层往上长的。AI 是从顶层往下长的。
  • CS：从底往上。先有晶体管，再有逻辑门，再有 ALU，再有 CPU，再有操作系统，再有编程语言，再有应用软件。每一层都建立在下一层已经被完整理解的基础上。你可以一路往下拆，拆到底层——晶体管只有开和关两个状态——你找到了不可再分的地基。层级之间是干净的依赖关系：上面依赖下面，下面不依赖上面。所以你能画出九层。
  • AI：从顶往下。先有了效果——"这个模型居然能回答问题"——然后人们开始往下拆："它是怎么做到的？"Transformer 论文 2017 年出来的时候，作者不知道 attention 矩阵里的某个权重对应着什么语义概念。到现在，你仍然没法像解释"为什么这段 C 代码编译出来是这个汇编"一样解释"为什么这个 prompt 让模型输出了这个回答"。层级之间不是干净的依赖关系——是互相渗透的、没凝固的、还在流动的。所以你的 AI 框架只有六层——不是因为遗漏，是因为有些层还没结晶到能被单独命名的程度。
第三层：复杂度来源不同
CS 的复杂度来自组合。AI 的复杂度来自涌现。
  • CS：一个 CPU 有几十亿个晶体管，但每个晶体管只做一件事——开或关。复杂度是"简单的零件按规则组合出来的"。所以你能拆——不是因为它简单，是因为它的复杂是可分解的。
  • AI：一个 1750 亿参数的模型，没有任何人专门训练它做翻译——它自己就会了。没有任何人教它"如果用户生气了你要道歉"——它自己就会了。这些能力不是任何一层设计出来的，是数据、架构、训练过程三者之间不可预测的相互作用产生的。涌现的东西没法用"这一层做了什么，上面那层依赖它什么"来拆——因为它在层与层之间的缝里自己长出来的。
CS 是建筑，AI 是气候。
建筑有楼层。气候有风向、洋流、云层——它们也分层，但层之间永远在交换物质和能量，你画的每一层都是暂时的快照，下一场暴雨就变了。
Part 1

一个人，用AI，做一个软件，技术上的活怎么拆？

不要按前端/后端/部署拆。按依赖顺序拆。

01
让它能看见

不管你的软件是什么——小程序、网页、App——第一件事是让界面出现在屏幕上。一个输入框、一个按钮、一个能显示数据的地方。不需要好看，不需要完整，但必须能看见。因为你和 AI 的协作需要一个可视化的锚点——你对着空气描述"我想要一个管理订单的系统"，AI 给你一段代码，你看不懂，你也不知道它跑起来是什么样。但如果它先给你一个在浏览器里能打开的页面——哪怕只有一个标题——你的伪代码就找到了第一个实物。你能说："好，现在在这个页面里加一个输入框。"

这一块的技术内容：HTML/CSS（或者小程序的 WXML/WXSS），以及你用的 AI 工具怎么把代码变成你能在屏幕上看到的东西。

02
让它能记住

你有了界面，用户填了数据，点保存——数据去哪了？刷新页面，数据还在吗？这是状态。软件和一张图片的区别是：软件有记忆。用户做了什么，软件要记住。新手最容易卡死在这一步——因为这一块需要你去碰那些 Python 替你藏起来的东西：数据存在哪、怎么拿回来、为什么刷新就没了。

这一块的技术内容：变量 → 数据结构（列表、字典）→ 存到本地 → 存到云端（数据库）。顺序不能颠倒。先让她在自己的电脑上跑通"存一个东西，关了再打开它还在"，再让她去想"别人也能用"这件事。

03
让它能出去

你的软件在自己电脑上跑得好好的——现在怎么让别人也能用？这就是部署。但一个人用 AI 做部署，不需要学微服务和 CI/CD。她只需要做一件事：把代码放到一个能让别人访问的地方。对网页来说，可能是 GitHub Pages 或者 Vercel。对小程序来说，可能是微信开发者工具上传。

这一块的技术内容：什么是服务器（一台永远开着的电脑）、什么是域名（别人找到这台电脑的地址）、以及 AI 能帮你做的 95% 的部署步骤中，哪 5% 你必须自己判断。

三块，按依赖顺序走——看见 → 记住 → 出去。每一块都能独立验证：界面出来了吗？数据存住了吗？别人能打开吗？不需要等全部做完才知道"对不对"。这不是前后端分工——分工是空间上的切分，依赖是时间上的切分。一个人不需要把活分给三个人，一个人需要知道先做哪块、再做哪块、做到哪一步算"这一块可以了，进下一块"。这就是用顺序替代复杂度。

弹药

不是一个字一个字写——是从菜篮子里拿

你们有没有想过一个问题：全世界那么多网站、那么多小程序——难道每个人都是从空白文件开始写的吗？

不是。程序员的工作方式，和很多人想象的不一样。他们不是拧螺丝造零件——他们是拿现成的轮子，装在自己的车上。

这个轮子仓库叫 GitHub。全球最大的代码托管平台——但你不用把它理解成「程序员用的东西」。你把它理解成：一个你可以免费拿走别人做好的东西，然后让 AI 帮你改成你的版本的地方。

GitHub 是什么（给没听过的人）
  • GitHub 是一个网站——github.com。你在上面可以看到别人公开的所有代码。
  • 它不是 App Store——App Store 给你成品，但不能拆开看里面、不能改。GitHub 给你半成品 + 全部配方。你不仅能跑，还能打开看里面怎么做的、改它、把它的一部分拆出来装到你的东西里。
  • 搜「landing page template」（落地页模板）、「portfolio website」（个人作品集网站）、「admin dashboard」（后台管理系统）——你会看到几百个已经写好的整站代码。
  • 你不需要看懂每一行。你只需要知道三件事：这是做登录页面的、这是做列表的、这是做按钮的。
怎么拿
  • 方法一：点网页上的绿色「Code」按钮 → Download ZIP → 解压 → 文件夹到你电脑上了。
  • 方法二（稍微进阶）：在命令行里打 git clone 链接——这个你后面会学，今天先知道存在。
拿了之后：AI 帮你改成你的
  • 打开 ChatGPT 或 Claude：「这个文件夹里有一个登录页面，帮我把它的标题改成「我的服装店」，背景色换成暖白色。还有，把用户名改成手机号输入框。」
  • AI 改完。你刷新浏览器。你的登录页就变成了你自己的。
  • 你没写一行代码。你做的是：找到对的半成品，说清楚你要改成什么样。
这才是真实世界的工作方式。做课的人不会告诉你这个——因为他们想让你觉得「必须学完所有语法才能做出东西来」。但你不是来学造轮子的。
你是来开车去你想去的地方。
🎬 现场演示（3 分钟）

1. 打开 github.com
2. 搜索「simple html website template」
3. 随便点进一个项目——往下翻，看到预览截图或 demo 链接
4. 点 Code → Download ZIP → 解压 → 打开 index.html
5. 「看，一个完整的网站，就是这么来的。」

下周开始，我们会一起做这件事——不是写代码，是找人已经写好的、让 AI 改。

Part 2

第一周你要做的是拆业务。那么，怎么拆？

拆到她能用一段话把每个阶段说清楚，然后 AI 能听懂为止。不多，不少。

一周结束时，她手里应该有三段话。
每段话不超过十行。
不是技术文档——是执行地图。
看见阶段

她应该拆出：谁，打开什么，看到什么，能做什么。

举例：不是"我要做一个订单管理系统"。是一个用户故事。

范例 · 看见

用户打开我的小程序，看到一个登录页面。输入手机号，点获取验证码，输入验证码，点登录。进来后看到一个列表——ta 之前提交过的所有订单。每个订单显示日期、状态、金额。底部有一个"+"按钮，点进去是提交新订单的页面。

这就是够了。不需要画原型图，不需要写 CSS。但她必须能说出第一步是什么、用户能在这一步做什么、下一步怎么去。每一个"看见"对应一个用户动作。她的业务是她自己的——她知道用户要干嘛。她只是从来没被要求用这种方式说出来。

记住阶段

她应该拆出：什么东西不能丢，放在哪。

这是最容易跳过的。她可能会说"用户填完点保存就行"。这时候要问她——保存在哪？关了再打开，还在吗？她不需要回答"存在 MySQL 数据库的 orders 表里"。她只需要回答：

范例 · 记住

用户提交的订单要一直留着，不管过多久再打开都能看到。用户自己的登录信息也要记住，下次不用重新登录。

两句话。第一句是业务数据——订单、记录、用户的输入。第二句是用户状态——谁在用这个软件，软件要知道。她用自然语言回答了"记住什么"，就够了。

出去阶段

她应该拆出：谁用，在哪用，用什么方式用。

范例 · 出去

这是我的服装店用的，我和店员用。需要一个网页版，在电脑上打开。或者一个小程序，顾客也能用。

这就够了。她不需要知道 Vercel 是什么，不需要知道域名怎么买。她只需要知道这个软件长在哪个载体上、谁在用它。剩下的，AI 会问她。

交付标准

一周结束时，她手里有什么

三段的完整范例放在一起：

①
看见
谁，打开什么，看到什么，能做什么。
②
记住
什么东西不能丢，放在哪。
③
出去
谁用，在哪用，用什么方式用。

不是一份完美无缺的产品需求文档。是一份她自己看得懂、AI 也看得懂、而且能按顺序一块一块往下推的执行地图。

她可以拿着第一段——"看见"——对 AI 说：照着这个做。她能判断做对了没有——因为她知道自己的业务长什么样。

两棵树，一条路，三段话。
