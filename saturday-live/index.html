模块 1

这是一门语言课

进入编程，首先应该记住的是，这是一门语言课。只是恰好语言的使用者不是人类，是计算机。

这是一门语言课，在整个过程中保持记住这一点，这会让你能够绕过障眼法，直取核心。

所以通感是语感。幸运的是，作为语言，它的历史比其它古老的人类语系要年轻很多。年轻意味着分支会短，语言与语言之间的差异会更小——为什么？很简单，因为是人类造的。语言的成长所基于的是人类的生命和社会的历史，语言是人类为了自组织而发展出的东西。而计算机，这门语言的使用者，也是人类制造的，人类客观的发展速度限制了造物的发展速度。

所以，建立通感并不是一件不可实现的事情。因为它的成立基础不是鸡血、情绪、勇气甚至承诺，而是客观事实：你用一个月、每天一小时去学习一门语言，建立了语感是自然而然的事情。

而我们要做的是，把无关项清理掉，保证你的每个小时都在对正确的目标精准地投入注意力——也即，不浪费你作为人类的"token"。

🔬 前沿AI注入
「不浪费你的 token」——这里可以引入 token 的概念。你的注意力就像 AI 的 token 预算——是有限的，是有成本的。你乱扔 prompt，AI 乱翻教材。我们能做的是让每一句对话都打在正确的地方。
模块 2

AI是你的老师，但你得给它教科书

AI（通用AI，当然了）是教师，但是手里没有固定的教材。或者说同时使用一万本教材，而一万本教材中的每一本，每读取你一句输入——也就是翻到下一页——就会跳到另一本教材。一万本教材的每一本每一页随机组合，你花了几个小时，却一本也没读明白。

LLM和人类都没做错什么，唯一的错是你不知道它在翻页，它不知道你在想什么。这是障碍，而非错误。

所以你的任务是找到自己的那本教科书，并且要求教师按照这本教科书循序渐进地教导你。这听起来是一个悖论，是吗？但对一个你要学习的东西进行外部性的把握，和对它进行内部性的理解，是两件不同的事情，而前者并不建立在后者之上。

那么第一周——整个课程中长达 1/4 的时间——为什么被用来给你们拆解需求？

你需要知道工具箱里有哪些工具，才能拆解自己需要什么。

🔬 前沿AI注入
这里可以讲 LLM 的注意力机制——不用术语，用比喻：「AI 读你的 prompt 时，它在同时看一万本书，但每本书只有一页被照亮。」也可以提上下文窗口（context window）——AI 能记住的对话长度是有限的，这也是为什么你需要教科书，不能靠无限闲聊。
模块 3

先认识工具，再拆需求

你不需要学会怎么造一把扳手，但你需要认识我们可以使用的东西有扳手、锤子、锯子；你需要知道：扳手能拧螺丝、锤子能敲钉子、锯子能截木头。

知道了这些，你才能把自己的需求——比如「我想做一个能管理用户订单的系统」——拆成：我需要一个界面让用户填信息（前端）、我需要数据存下来不会丢（后端）、我需要在界面和数据之间有个通道（API）。

这个拆解能力不是零基础就能自动获得的。它需要有人先打开工具箱，把工具一件件拿出来给你看。在计算机中，有前端、后端、数据库——这是前端能做的，这是后端能做的，这是数据库能做的。然后，你才能拿着自己的业务需求，对着 AI 说：「好，我的需求需要这个、这个，还有这个。」

🏗 CS硬核注入
这里放出 CS 知识树 Day1 版——前端、后端、数据库三个分支。「这就是计算机的工具箱，三样东西。接下来一个月你不需要学更多类别——只需要让这三样东西在你脑子里越来越清晰。」
🔬 前沿AI注入
做一个「AI 工具箱快闪」——给他们看 ChatGPT/DeepSeek 对话框、Claude Code 终端界面、Cursor IDE 截图。不是教怎么用，是让他们看见「这些就是你的扳手、锤子、锯子」。消除「我不知道市面上有什么」的焦虑。如果有条件，展示一个真实的对话记录——你自己跟 AI 说「我想做一个能管理用户订单的系统」，AI 返回了什么。
模块 4

那堵绕不开的墙

语言的学习中不可跳过、占据大量时间成本的一个环节是什么？对，是记忆。

理解很重要。不幸的是理解更具有吸引力，而记忆则没有。所以很多课程会通过给出理解，模糊或削弱记忆的时间占比。因为付费课程首先是商品、然后是教育，如果过于痛苦，消费者会流失一部分，违背商业利润最大化原则。

有些课程是故意的：知道记忆重要，但选择了最大化留存率而非最大化学习效果。

有些课程是不知道的：设计者自己也没意识到语言学习里那堵绕不开的墙是记忆，于是用理解把它盖过去。

客观结果一样：人们以为自己学会了，离开课程，打开 AI，发现还是一本教材都读不完。

而实现记忆很重要的一个动作是重复。并非重复循环，而是——举例来说，假设你有 3 块具有先后顺序的内容需要学习，那么，如果你学完第 3 块，感到困惑，一个很好的方法是回去看看第 1 块。看一遍，似懂非懂，去动手、推推你的节点、做点什么，过两天再看一遍，这两天动手做的东西会让你比之前懂一些，知识之间会互相哺育生长。

🔬 前沿AI注入
你不需要背代码，AI 会帮你写。你需要记住的是结构——这个需求需要前端+后端+数据库。你跟 AI 说话时需要的不是语法，是结构。
模块 5

三张纸，三棵树

那到底要记忆什么？系统。

1. 一些知识，理解AI是怎么工作的——如果有哪个部分能做到消解你的AI焦虑，或许只会是在这里。因为了解基础后，再看新鲜前沿的东西，会觉得有迹可循，而不是 out of nowhere。
2. 一些知识，理解CS是怎么工作的——基础设施。
3. 一些指令，你能用什么、怎么用AI——这里的基础是第 1 条。
4. 一些指令，你能用什么、怎么用CS——这里的基础是第 2 条。

仅此而已。简谐的互文结构。

三张纸，三棵树：一个系统的知识树将会被放在一张纸上生长，每节课都会是在这个树上再长一点，但永远在同一棵树上。这就是系统之所以为系统的系统性。

AI 一张纸，CS 一张纸。在此基础上，你将要拆出来的东西，你将用接下来一个月构建的东西，也应该是在一张纸上。

🏗 CS硬核注入（核心）
放出 CS 知识树 Day1 版——前端、后端、数据库、API 四个分支。做一个「CS 的层」快闪——从二进制到 Python 的抽象层级，30 秒。不是讲，是让他们感受：「每一层都有人帮你做了，你站在最上面一层。——Abstraction。」然后引出伪代码和抽象的概念。
🔬 前沿AI注入（核心）
放出 AI 知识树 Day1 版——模型、Prompt、上下文、输出控制四个分支。「这棵树今天只有四个分支。但每一周我们会在上面多长一点——比如到第四周你会知道什么是 RAG，什么是 Agent，什么是 fine-tuning。但你不需要今天就焦虑那些。」做一个 30 秒「前沿快闪」——展示四周可能会碰到的新东西：MCP、Agent、Vibe Coding、AI IDE。不是讲——是让他们看见「这些东西都在那棵树上，我们慢慢到」。

告诉他们在哪可以自己跟踪前沿：Hacker News、Twitter/X 上的 AI 开发者、GitHub Trending。但不要求跟踪——它是背景音，不是考试。
基石概念

伪代码 & 抽象

在开始「看见→记住→出去」之前，先种下两个基石概念。它们是接下来所有技术内容的地基。

Pseudocode · 伪代码

Pseudocode is human-readable instructions that often describe the steps of an algorithm. The ability to create pseudocode is central to one's success in both this class and in computer programming.

For example, considering the third algorithm above, we could compose pseudocode as follows:

1 Pick up phone book 2 Open to middle of phone book 3 Look at page 4 If person is on page 5 Call person 6 Else if person is earlier in book 7 Open to middle of left half of book 8 Go back to line 3 9 Else if person is later in book 10 Open to middle of right half of book 11 Go back to line 3 12 Else 13 Quit

Pseudocoding is such an important skill for at least two reasons. First, when you pseudocode before you create formal code, it allows you to think through the logic of your problem in advance. Second, when you pseudocode, you can later provide this information to others that are seeking to understand your coding decisions and how your code works.

Notice that the language within our pseudocode has some unique features. First, some of these lines begin with verbs like pick up, open, look at. Later, we will call these functions. Second, notice that some lines include statements like if or else if. These are called conditionals. Third, notice how there are expressions that can be stated as true or false, such as "person is earlier in the book." We call these boolean expressions. Finally, notice how there are statements like "go back to line 3." We call these loops.

These building blocks are the fundamentals of programming.

Abstraction · 抽象

Along with pseudocoding, abstraction is an essential skill and concept within computer programming. Abstraction is the act of simplifying a problem into smaller and smaller problems.

By learning programming, you will be far more prepared for future learning in other programming languages like Python. Notice how programmers have used abstraction to build off the work of other programmers. Rather than programming in ones and zeroes, programming languages were created to abstract away from the incredibly challenging task of programming in binary to more and more easy-to-use programming languages. We can stand on the shoulders of others.

🏗 CS硬核注入
这里可以做 30 秒「抽象层级」快闪——二进制 → 汇编 → C → Python → AI 对话。让学员看见：「从 0 和 1 到你今天对 AI 说一句话——每一层都有人替你做了。你站在巨人的肩膀上，不是在地上。」这是整个课程中最能消解「我不配」焦虑的时刻之一。
模块 6

一个人，用AI，做一个软件

一个人，用 AI，做一个软件，技术上的活怎么拆？

不要按前端/后端/部署拆。
按依赖顺序拆。

分工是空间上的切分——谁做什么。依赖是时间上的切分——先做什么、后做什么、做到哪一步算「这一块可以了，进下一块」。一个人不需要把活分给三个人，一个人需要知道先做哪块、再做哪块。

这就是用顺序替代复杂度。

第一块

让它能看见

不管你的软件是什么——小程序、网页、App——第一件事是让界面出现在屏幕上。一个输入框、一个按钮、一个能显示数据的地方。不需要好看，不需要完整，但必须能看见。

因为你和 AI 的协作需要一个可视化的锚点——你对着空气描述「我想要一个管理订单的系统」，AI 给你一段代码，你看不懂，你也不知道它跑起来是什么样。但如果它先给你一个在浏览器里能打开的页面——哪怕只有一个标题——你的伪代码就找到了第一个实物。你能说：「好，现在在这个页面里加一个输入框。」

这一块的技术内容：HTML/CSS（或者小程序的 WXML/WXSS），以及你用的 AI 工具怎么把代码变成你能在屏幕上看到的东西。

🔬 前沿AI注入
现场演示（整场直播的第一个「哇」点）：打开 ChatGPT，输入「帮我写一个 HTML 页面，上面有一个标题「我的第一个软件」和一个按钮」。30 秒——从一句话到一个能看的页面。让他们看见从 prompt 到可视界面的完整路径。
第二块

让它能记住

你有了界面，用户填了数据，点保存——数据去哪了？刷新页面，数据还在吗？这是状态。

软件和一张图片的区别是：软件有记忆。用户做了什么，软件要记住。新手最容易卡死在这一步——因为这一块需要你去碰那些 Python 替你藏起来的东西：数据存在哪、怎么拿回来、为什么刷新就没了。

这一块的技术内容：变量 → 数据结构（列表、字典）→ 存到本地 → 存到云端（数据库）。顺序不能颠倒。先让她在自己的电脑上跑通「存一个东西，关了再打开它还在」，再让她去想「别人也能用」这件事。

🏗 CS硬核注入（核心）
用生活比喻，不用术语：
变量 = 一段有名字的内存。像贴了标签的抽屉。「用户名 = 张三」→ 抽屉标签叫「用户名」，里面放的是「张三」。
数据结构 = 怎么把抽屉组织起来。列表 = 排队的篮子（第1个、第2个…）；字典 = 贴标签的抽屉组（「姓名:张三, 年龄:22」）。
数据库 = 在云端不会消失的抽屉柜。关了电脑数据还在。数据库说的语言叫 SQL，长这样：SELECT * FROM users——你不需要学会写，但你要知道它在说什么。
第三块

让它能出去

你的软件在自己电脑上跑得好好的——现在怎么让别人也能用？这就是部署。

但一个人用 AI 做部署，不需要学微服务和 CI/CD。她只需要做一件事：把代码放到一个能让别人访问的地方。对网页来说，可能是 GitHub Pages 或者 Vercel。对小程序来说，可能是微信开发者工具上传。

这一块的技术内容：什么是服务器（一台永远开着的电脑）、什么是域名（别人找到这台电脑的地址）、以及 AI 能帮你做的 95% 的部署步骤中，哪 5% 你必须自己判断。

🏗 CS硬核注入
三个比喻，30 秒搞定：
服务器 = 一台永远不关机的电脑。你的代码跑在上面，别人随时能访问。
域名 = 电话号码 vs 通讯录名字。IP 是号码，域名是名字。
HTTP = 你在浏览器输入一个网址，本质上在对一台远方的电脑说：「请把那个页面给我。」
🔬 前沿AI注入
展示 GitHub Pages 部署——告诉他们「你不需要学 DevOps。你只需要把这个文件夹拖到这里。剩下的 AI 教你。」可以提到 Vercel、Netlify 这些一键部署平台——现代部署已经不是 2015 年的难度了。AI 能帮你做部署的 95%，剩下 5% 是你必须自己判断的：你的项目是网页还是小程序？你需要 GitHub Pages 还是微信开发者工具？AI 不会替你选，但它会帮你做完你选的路。
收束

接下来一个月你会怎么过

三块，按依赖顺序走——看见 → 记住 → 出去。每一块都能独立验证：

①
看见
界面出来了吗？
②
记住
数据存住了吗？
③
出去
别人能打开吗？

不需要等全部做完才知道「对不对」。走到哪一步，你都知道自己在哪。

你会发现——后面的每一周，都在这三块的框架里。只是每块的内容在变深。
